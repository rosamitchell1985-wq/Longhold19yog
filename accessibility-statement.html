Accessibility statement

What we have built, what we know is imperfect, how to report a barrier, and how quickly we respond.

Effective date: 08/27/2026  ·  Last updated: 08/27/2026

1. Our target

Longhold Yoga aims to conform to the Web Content Accessibility Guidelines (WCAG) 2.1 at Level AA. That is the standard the site is built against and the standard we hold ourselves to when something is reported.

This is a statement of intent and current practice, not a certification. The site has not yet been through an independent third-party audit. When it has been, this page will say so, name the auditor and give the date.

2. What is implemented

Structure and navigation

  • Semantic HTML5 landmarks on every page: a single header, nav, main and footer, with section headings in a logical order.
  • A skip-to-content link as the first focusable element on every page, visible as soon as it receives focus.
  • One h1 per page, with heading levels that descend without skipping.
  • Breadcrumb navigation on interior pages, marked up as a labeled navigation region.
  • The current page is marked in the navigation with aria-current="page" as well as with a visible underline, so the state is not conveyed by color alone.

Keyboard

  • Every interactive element is reachable and operable by keyboard alone, including the mobile menu, the Learn dropdown, the FAQ accordions, the pose filters, the sequence timer and the cookie banner.
  • Focus indicators are visible on every focusable element and are never removed. They use a 2px outline with an offset so they stay visible against tinted backgrounds.
  • The Escape key closes the mobile menu and the navigation dropdown, returning focus to the control that opened it.
  • Focus order follows the visual order of the page.

Color and contrast

  • Body text meets or exceeds a 4.5:1 contrast ratio against its background. Ink on the page background measures approximately 14:1 and the muted body color approximately 6.3:1.
  • Placeholder text, helper text and error text all meet 4.5:1. Placeholder text is never used in place of a label.
  • The clay accent color is used for rules, borders and ornament only, never for text, because it does not meet a text contrast ratio.
  • No information is conveyed by color alone. Form errors carry text and a border-weight change; the active nav item carries an underline and an ARIA attribute.

Forms

  • Every input has a visible label that is programmatically associated with it.
  • Errors appear inline, directly below the field they relate to, in text, and the field is marked aria-invalid.
  • On submission, focus moves to the first field with an error. On success, focus moves to the confirmation message.
  • Required fields are marked in the markup rather than only with an asterisk.
  • Touch targets on interactive elements are at least 44 by 44 CSS pixels with spacing between them.

Images and media

  • Every photograph has descriptive alternative text written for someone who cannot see it.
  • Every image carries explicit width and height attributes so the layout does not shift as images load.
  • Images below the fold are lazy-loaded; images in the fold are not, so they appear promptly.
  • There is no audio or video anywhere on this site, so there is nothing that auto-plays and nothing that needs captions.
  • Decorative graphics are avoided. Where an icon-like character is used it is marked aria-hidden and accompanied by text.

Motion

  • All animation on this site is a 250 millisecond fade and rise on section entry. There is no parallax, no scroll hijacking, no auto-advancing carousel and no infinite loop.
  • Content is visible by default. Reveal animation is added only when JavaScript and the necessary browser support are present, so nothing ever ships blank.
  • prefers-reduced-motion: reduce is respected everywhere. Under that setting, transitions are disabled, smooth scrolling becomes instant, and the breath-pacing bar stops animating and displays its pattern as plain text instead.
  • The breath-pacing animation is off by default on every page and only starts when you press the button.

Reading and layout

  • Body text is 17px with a 1.8 line height, in a column capped at roughly 65 to 75 characters.
  • The page reflows to a single column at 320px width without horizontal scrolling and without loss of content.
  • Text can be resized to 200 percent without breaking the layout, and browser zoom is not disabled.
  • Wide content such as tables scrolls within its own container rather than forcing the page to scroll sideways.
  • Every page has a print stylesheet that strips navigation, timers and advertising, so a sequence prints legibly as a practice handout.

3. Accessibility in the instruction itself

Accessibility on this site is not only a technical matter. It also shapes what we write.

  • Every pose guide includes at least two prop-supported options, written as equal alternatives rather than as reduced versions.
  • Chair and wall alternatives appear throughout the site, and an entire sequence, the Desk Reset, needs nothing but a chair.
  • Every sequence has a written beginner modification path naming a specific alternative for each pose, rather than a vague instruction to modify.
  • Hold times are given in seconds and breaths, not as "a few breaths", so a practice can be followed without guesswork.
  • Sanskrit terms carry a plain pronunciation guide.
  • The teacher directory asks every listing to state whether the space has step-free access and whether chairs are available.

4. Known limitations

Stated plainly, because a statement that claims perfection is not worth reading.

  • The site has not been independently audited. Testing so far has been manual keyboard and screen reader testing plus automated checks, which catches a great deal but not everything.
  • The sequence timer announces changes visually. Pose changes are exposed through a live region, but the experience of following a timed sequence by screen reader alone has not been tested extensively with real users, and we expect to find problems there.
  • Photographs are illustrative rather than instructional. The alternative text describes what the photograph shows, but the instruction itself lives in the written text, which is deliberate: nothing on this site depends on being able to see an image.
  • Third-party advertising is outside our control. Advertisements are served by external vendors, and we cannot guarantee that a given advertisement meets WCAG. We can and do block specific advertisements when they are reported.
  • Downloadable PDFs are being remediated. The planned digital products need to be tagged for screen reader use. Until they are, an accessible plain-text or HTML alternative is available on request at no charge.

5. Compatibility

The site is built to work with current versions of the major browsers on desktop and mobile, and with the screen readers commonly paired with them. It does not require JavaScript to read: with JavaScript disabled, every page's content, navigation links and text remain fully available. The interactive extras, meaning the mobile menu, the filters, the timer and the breath pacer, need JavaScript to function.

6. Report a barrier

If any part of this site is difficult or impossible for you to use, please tell us. This is the most useful thing anyone can do for the accessibility of this site, and it is taken seriously.

  • Email: hello@longholdyoga.com with "accessibility" in the subject line.
  • Form: the contact form, choosing the accessibility category.
  • Phone: +1 (503) 555-0147, Monday to Friday, 9:00 a.m. to 5:00 p.m. Pacific Time.
  • Mail: Longhold Yoga, 1412 SE Cortland Avenue, Suite 3, Portland, OR 97202, United States.

Useful things to include, if you can: the page address, what you were trying to do, what happened instead, and which browser and assistive technology you were using. Any of that helps, and a report without any of it is still worth sending.

What happens next

  • We acknowledge every report within 2 business days.
  • We give you an assessment and a plan within 10 business days.
  • Barriers that block access to instructional content are prioritized above everything else in the queue.
  • If a fix will take time, we offer the content in an alternative format, at no charge, in the meantime.
  • Every report is logged, and this page is updated when a known limitation is resolved.

7. Formal complaints

If our response does not resolve the problem, you can escalate by writing to the mailing address above marked for the attention of the site owner. In the United States, you may also contact the Civil Rights Division of the Department of Justice regarding accessibility complaints.
